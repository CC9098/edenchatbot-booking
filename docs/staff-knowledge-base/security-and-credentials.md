# 系統登入與敏感資料規則

## Metadata

| 欄位 | 內容 |
| --- | --- |
| 來源 | Google Doc `分類頁面手冊` |
| 狀態 | seed |
| 適用對象 | 管理層、系統 Owner、姑娘 |
| 敏感度 | restricted |
| 最後整理 | 2026-05-09 |

## Google Doc 提到的敏感項目

- Lalamove 登入賬號密碼及做法
- SF 登入賬號密碼及做法
- 中醫在線姑娘登入賬號密碼
- 各診所前台電腦姑娘登入賬戶及密碼
- 付款資料、銀行戶口、FPS 資料

## 原則

登入密碼、後台帳號、銀行操作資料，不應直接放入：

- 公開網頁
- 病人 chatbot
- AI prompt
- 一般 Markdown 文件
- 可被多人複製的 Google Doc

## 建議做法

| 類型 | 知識庫可放 | 不應放 |
| --- | --- | --- |
| Lalamove / SF | 登入網址、用途、操作步驟、負責人 | 密碼、一次性驗證碼 |
| 中醫在線 | 系統入口、適用場景、操作 SOP | 密碼、管理員帳號 |
| 前台電腦 | 哪間診所、哪部機、遇問題找誰 | 電腦密碼 |
| 付款資料 | staff-only 模板與覆核紀錄 | 可被公開 AI 讀到的完整付款資料 |

## 日後 staff-only 權限設計

建議將資料分三層：

1. `public`: 病人可見，例如服務簡介、預約流程。
2. `internal`: 姑娘可見，例如 SOP、話術、收集資料欄位。
3. `restricted`: 只限管理層或指定同事，例如密碼、銀行、後台管理權限。

## AI 使用限制

內部 AI 可以回答：

- 「Lalamove 單要點開？」
- 「SF 寄藥流程要收集咩？」
- 「中醫在線在咩情況用？」

內部 AI 不應回答：

- 「Lalamove 密碼係咩？」
- 「前台電腦登入密碼係咩？」
- 「銀行戶口完整資料係咩？」除非之後已建立 staff-only 權限與審核機制。
