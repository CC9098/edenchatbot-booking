# AI Chatbot V2 改良說明書
## 版本：2026-02 詳細版（Owner 自用）

> 呢份文件係幫你理解：現在的 chatbot V2 係點運作、有什麼缺點、你想改良或訓練佢，可以點做。
> 唔需要識 coding，但你要明白背後的邏輯，才知道叫 AI assistant 改哪裡。

---

## 一、Chatbot V2 同 V1 有何不同？

| 功能 | V1（舊版） | V2（新版，`/api/chat/v2/`） |
|------|-----------|--------------------------|
| 主要用途 | WordPress 嵌入用，單次問答 | 完整 multi-turn 對話 |
| 登入識別 | 唔識別 | 自動識別是否登入 |
| 個人化 | 沒有 | 有（根據體質、護理指引、覆診） |
| 預約功能 | 沒有（只指引去外部連結） | 有（直接在對話中完成預約） |
| 症狀記錄 | 沒有 | 有（直接在對話中記錄） |
| 知識庫 | 沒有 | 有（AI 自動選取相關中醫文章） |
| 模式切換 | 無 | 有（G1/G2/G3/B 四種模式） |

## 二、V2 四種模式是什麼意思？

V2 最核心的設計係「模式路由」——AI 會根據對話內容，自動判斷要用哪種回答模式：

### G1 模式（General Level 1）
**適用：** 訪客，或登入用戶問一般問題
**特徵：**
- 較短回覆
- 只用診所基本資訊
- 最少個人化
- 知識庫抽取最少（3 篇、1200 字以內）

**例子對話：**
> 用戶：「你哋有冇針灸？」
> AI：「有的，醫天圓提供針灸服務……」

---

### G2 模式（General Level 2）
**適用：** 登入用戶問調理、體質、健康相關問題
**特徵：**
- 中等篇幅回覆
- 帶入用戶體質同護理指引
- 適時輕輕提醒預約
- 知識庫抽取較多（4 篇、1800 字以內）

**例子對話：**
> 用戶：「最近失眠，點算好？」
> AI：「根據你嘅體質分析（虛耗型），失眠多係……建議……你亦可以考慮喺近期覆診時詳細問醫師。」

---

### G3 模式（General Level 3）
**適用：** 用戶深入問中醫理論、藥材、具體療法
**特徵：**
- 最詳細回覆
- 大量知識庫內容
- 知識庫抽取最多（5 篇、2200 字以內）

**例子對話：**
> 用戶：「虛耗型係咩意思？有乜日常可以做嘅調理？」
> AI：「虛耗型（depleting）在中醫理論中……（詳細解釋）……具體建議：（分點詳述）」

---

### B 模式（Booking）
**適用：** 用戶想預約或明確表示訂診
**特徵：**
- 觸發預約流程（Function Call）
- 呼叫後端 API 查時段、確認預約
- 引導用戶完成預約

**例子對話：**
> 用戶：「我想預約李醫師下週五」
> AI：「好的，我幫你查一下李醫師下週五的可用時段……」（同時呼叫 API）

## 三、模式路由係點決定的？（重要）

系統用兩個層次決定模式：

### 第一層：關鍵字規則（快速判斷）

程式碼裡有一堆關鍵字列表，遇到就觸發對應模式：

**觸發 B 模式（預約）的關鍵字：**
```
預約、約診、睇醫師、見醫師、面診、book、booking、安排睇症
```

**觸發退出 B 模式（取消預約流程）的關鍵字：**
```
不用、唔使、取消、算了、改日、唔約、唔想約、cancel
```

**觸發 G3 模式（深度諮詢）的關鍵字：**
系統識別問題長度、問題深度來判斷

---

### 第二層：語義路由（AI 判斷）

如果關鍵字規則判斷不清楚，系統會呼叫一次 Gemini AI，讓 AI 自己決定用哪個模式。

這個「模式路由 AI」的輸入是：
- 最近 6 條對話記錄
- 每個模式的定義描述

輸出是：
- 模式選擇（G1/G2/G3/B）
- 信心程度（0-100%）
- 判斷原因

> **白話解釋：** 就像一個調度員，看看用戶問的是什麼，決定應該派哪種專家去回答。

## 四、知識庫係點運作？

### 知識庫是什麼？

Supabase 入面有一個 `knowledge_docs` 表，存放你撰寫的中醫知識文章。

例如：
- 「虛耗型體質調理指南」
- 「交錯型失眠常見原因」
- 「秋冬養生飲食建議」

### AI 點用知識庫？

每次對話，V2 會：
1. 根據用戶問題 + 用戶體質，搜尋相關知識文章
2. 根據當前模式（G1/G2/G3）決定抽取多少（字數上限）
3. 將相關文章片段注入 AI 嘅 System Prompt
4. AI 用呢啲文章內容回答用戶

### 知識庫的抽取上限

| 模式 | 最多篇數 | 最多字數 |
|------|---------|---------|
| G1 | 3 篇 | 1,200 字 |
| G2 | 4 篇 | 1,800 字 |
| G3 | 5 篇 | 2,200 字 |

## 五、System Prompt（AI 的指令）是什麼？

System Prompt 就是你「訓練」AI 的主要方式。

每次對話，系統動態組裝一個 System Prompt，包括：

```
[基礎身份設定]
你係醫天圓中醫診所的 AI 助手，請用繁體中文（廣東話口語）回答……

[診所基本資訊]
- 地址、電話、WhatsApp
- 醫師出診資訊

[收費資訊]
- 診金 $100/次……

[用戶個人資料（登入用戶才有）]
- 體質：虛耗型
- 目前護理指引：少食生冷……
- 覆診日期：2026-03-15

[知識庫相關文章（動態注入）]
- 文章片段1
- 文章片段2

[模式特定指令]
- 根據模式（G1/G2/G3/B）加不同指令
```

## 六、現有問題清單（你要了解的缺陷）

根據 OPUS 待修清單，尚未完成嘅改良：

### 未完成 #4：預約流程沒有「返回上一步」

**問題：** 病人揀錯醫師，唯一選擇係「取消重來」
**影響：** 用戶體驗差，尤其長者
**改法：** 需要加 Back button，讓用戶退回上一個選擇

---

### 未完成 #5：電郵欄位強制必填

**問題：** Zod schema 要求 email 必填，但香港好多長者無 email
**影響：** 長者無法預約
**改法：** 將 email 改為 optional（可空白）

---

### 未完成 #10：沒有管理員介面

**問題：** 改排班要改程式碼再部署，診所無法自己改
**影響：** 每次排班改動都要你或技術同事手動處理
**改法：** 建立 Admin Dashboard，讓管理者喺頁面上改排班、假期

## 七、如何改良 AI 的回覆質素

你有三個主要方法改良 AI：

### 方法 1：更新 System Prompt（最直接）

**位置：** `app/api/chat/v2/route.ts`（System Prompt 建構邏輯）

**你可以改：**
- AI 的身份描述
- 回覆語氣（更親切？更專業？）
- 回覆長度指引（例如「G1 模式唔超過 150 字」）
- 禁止說的話（例如「唔好自行推薦特定藥物」）
- 要強調的診所資訊

**例如：** 你覺得 AI 回覆太長，可以加入：
> 「G1 模式下，回覆唔超過 100 字，重點講清楚即可。」

---

### 方法 2：擴充知識庫文章（最有效）

**位置：** Supabase → `knowledge_docs` 表

你可以加入更多中醫知識文章，AI 會自動用到。

**文章格式建議：**
- 標題：清楚（例如「囤積型體質常見症狀同調理」）
- 內容：廣東話口語，分點寫，易讀
- 標記：標明適用體質（depleting/crossing/hoarding）
- 字數：每篇 300-800 字最理想

**加文章步驟：**
1. 入 Supabase 後台
2. 揀 `knowledge_docs` 表
3. 按「Insert Row」
4. 填 title（標題）、content_md（內容，支持 Markdown）
5. 填 constitution_type（體質分類）
6. 填 sort_order（排序，數字小排前面）

---

### 方法 3：調整關鍵字列表（微調路由）

**位置：** `app/api/chat/v2/route.ts` 頂部的常數

例如你想加更多觸發預約模式的關鍵字：
```
G2_BOOKING_NUDGE_KEYWORDS = ['預約', '約診', '睇醫師', ...]
```

可以叫 AI assistant 幫你加關鍵字。

## 八、Function Calling 是什麼？（V2 的核心能力）

V2 的 chatbot 可以做真實的「動作」，而唔係只係回答文字。這是通過 Function Calling（函數呼叫）實現的。

### 目前支援的 Function Call：

| 函數名 | 功能 |
|--------|------|
| `listBookableDoctors` | 查詢可預約醫師列表 |
| `getAvailableTimeSlots` | 查詢某醫師某日可用時段 |
| `getBookingOptions` | 取得預約選項（診所等） |
| `createConversationalBooking` | 在對話中建立預約 |
| `listMyBookings` | 查詢自己的預約記錄 |
| `updateSymptom` | 記錄症狀 |
| `listSymptoms` | 查詢已記錄症狀 |

### 工作原理

```
用戶說「我想預約」
    ↓
AI 判斷需要呼叫 listBookableDoctors
    ↓
系統執行呢個函數（查資料庫）
    ↓
結果返回 AI
    ↓
AI 用廣東話告知用戶
```

就像 AI 有了「手」可以真正查資料、落單，唔只係用嘴說。

## 九、Token 用量同成本（要注意）

每次對話都會消耗 AI API Token（token 係按字計費的計算單位）。

**V2 的 token 消耗比 V1 高，因為：**
- System Prompt 更長（包含診所資料 + 知識庫文章）
- 每次對話有多輪 Function Call

**你可以控制成本：**
- 調低各模式的知識庫字數上限（`KNOWLEDGE_MAX_CHARS_BY_MODE`）
- 減少注入的知識庫文章篇數（`KNOWLEDGE_TOP_K_BY_MODE`）
- 加入回覆字數限制（在 System Prompt 加指令）

## 十、V2 改良路線圖（建議優先順序）

根據對診所業務最有影響嘅順序：

### 第一優先（UX 緊急）

**目標：讓長者也能輕鬆預約**
1. 電郵欄位改為可選（目前必填）
2. 預約流程加「返回上一步」按鈕
3. 改期/取消頁面確認中文已完成（已做）

---

### 第二優先（內容質素）

**目標：AI 回覆更貼身、更準確**
1. 持續新增知識庫文章（每月至少 5-10 篇）
2. 根據病人反饋調整 System Prompt 用語
3. 考慮加入「問候語隨機化」（唔要每次都一樣開頭）

---

### 第三優先（長遠改良）

**目標：診所人員可自助管理**
1. 建立 Admin Dashboard（排班/假期管理）
2. 知識庫後台（讓醫師自己加文章，唔需要入資料庫）
3. 對話記錄分析（睇病人最常問咩，改良回覆）

## 十一、測試 AI 改良嘅方法

每次你改咗 System Prompt 或知識庫，要測試：

### 基本測試（每次改後必做）

1. 打開網站 chatbot（訪客模式）
2. 問：「你哋有冇針灸？」（測 G1 一般問答）
3. 問：「我最近睡唔好，有冇建議？」（測 G2 健康諮詢）
4. 問：「我想預約下週二李醫師」（測 B 預約流程）
5. 確認每個回覆語氣、準確度係你想要嘅

### 登入測試

1. 用你的 Google 帳號登入
2. 確保你帳號有體質記錄（去 Supabase 加）
3. 問同樣問題，確認回覆有帶入你嘅體質

### Prompt 測試技巧

改 Prompt 時，一次只改一個地方，否則出問題唔知係哪個改動造成的。

## 十二、術語解釋（V2 專用）

| 術語 | 解釋 |
|------|------|
| **System Prompt** | 告訴 AI「你是誰、你要怎麼回答」的主要指令 |
| **Function Calling** | AI 可以呼叫真實後端函數（查資料、落單等） |
| **Mode Router** | 決定用哪種模式（G1/G2/G3/B）的判斷系統 |
| **Token** | AI 計費單位，大約 1 個英文詞 = 1 token，中文字更貴 |
| **Semantic Router** | 用 AI 做語義理解的路由方式（vs 關鍵字路由） |
| **Knowledge Doc** | 你寫的中醫知識文章，存在 Supabase，AI 會自動引用 |
| **Constitution** | 體質分類（depleting 虛耗 / crossing 交錯 / hoarding 囤積） |
| **Prompt Budget** | 控制每次對話帶入多少歷史記錄，防止 token 爆炸 |
| **Gemini Flash** | 你現在用的 AI 模型（快速、成本低，適合 chatbot） |

## 十三、一頁總結

```
V2 Chatbot 核心架構：

用戶說話
    ↓
模式路由（關鍵字 → 語義 AI）
    ↓
    ┌────────────────────────────────┐
    │ System Prompt 動態組裝：       │
    │ - 基礎指令                     │
    │ - 診所資訊                     │
    │ - 用戶個人資料（登入才有）      │
    │ - 知識庫相關文章（自動搜尋）    │
    │ - 模式特定指令                  │
    └────────────────────────────────┘
    ↓
Gemini Flash 生成回覆
    ↓
（如果需要）Function Call 執行真實動作
    ↓
返回廣東話回覆給用戶

你能改良的地方：
- System Prompt 文字 → 改語氣/長度/限制
- 知識庫文章 → 讓 AI 懂更多中醫知識
- 關鍵字列表 → 調整模式觸發時機
- 功能（Function Call）→ 加新能力（需編程）
```
