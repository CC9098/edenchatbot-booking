## 三、環境變數（`.env`）逐個解釋

> 環境變數 = 敏感設定，唔放入程式碼，放喺 Vercel 後台同本地 `.env` 檔案

| 變數名 | 用途 | 在哪裡設定 |
|--------|------|-----------|
| `GEMINI_API_KEY` | Google Gemini AI API 金鑰 | Google AI Studio |
| `DATABASE_URL` | Neon PostgreSQL 連接字串 | Neon 後台 |
| `GOOGLE_CLIENT_ID` | Google OAuth 應用 ID | Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | Google OAuth 應用密鑰 | Google Cloud Console |
| `GOOGLE_REFRESH_TOKEN` | 長期 Google API 授權 Token | 一次性手動獲取 |
| `BASE_URL` | 你系統的公開域名 | 例如 `https://your-project.vercel.app` |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 項目 URL | Supabase 後台 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 公開 Key | Supabase 後台 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 管理 Key（後台專用） | Supabase 後台 |

**重要：**
- `BASE_URL` 唔設好，確認電郵內的改期/取消連結會壞
- `SUPABASE_SERVICE_ROLE_KEY` 唔好洩露，這個 key 有全資料庫管理權

## 四、兩個資料庫的分工

你的系統有兩個資料庫，不是一個，要區分清楚：

- `holidays`：假期設定

- `doctors`：醫師基本資料

## 五、Google Calendar 點運作

**原理：** 你的 Google 帳號下有幾個 Calendar，每個 Calendar 代表一位醫師喺某診所的排班。

**每次有人查詢可用時段：**
1. 系統計算某日的理論可預約時段（根據排班設定）
2. 調用 Google Calendar API `freeBusy` 查詢哪些時段已被佔用
3. 排除已佔用時段，返回可用時段給用戶

**每次有人預約成功：**
1. 系統呼叫 Google Calendar API 建立一個 Event
2. Event 會出現喺醫師的 Calendar 上
3. 防止重複預約（Double booking）

**注意：** 如果 `GOOGLE_REFRESH_TOKEN` 過期，Google Calendar 功能會完全失效。

## 六、Gmail 電郵系統

**寄件者：** 使用你設定嘅 Google 帳號發送（通過 OAuth 授權）

**觸發時機：**
1. 預約成功 → 即時發確認電郵
2. 改期成功 → 即時發新確認電郵
3. 取消成功 → 即時發取消確認電郵
4. 預約前 24 小時 → 提醒電郵（由 cron 任務發送）

**電郵模板位置：** `lib/gmail.ts`

**電郵連結原理：** 改期/取消連結格式是：
```
https://[BASE_URL]/reschedule?token=[唯一token]
https://[BASE_URL]/cancel?token=[唯一token]
```
Token 有有效期，過期後連結失效。

## 九、常見錯誤排查

### 問題：AI chatbot 無法回覆

**排查步驟：**
1. 確認 `GEMINI_API_KEY` 有設定且有效
2. 去 Vercel 後台看最近 Function logs
3. 錯誤訊息通常係「GEMINI_API_KEY is not configured」

### 問題：預約成功但 Google Calendar 沒有事件

**排查步驟：**
1. 確認 `GOOGLE_REFRESH_TOKEN` 未過期
2. 確認 `GOOGLE_CLIENT_ID` 同 `GOOGLE_CLIENT_SECRET` 正確
3. Vercel logs 搵 `[google-calendar]` 字眼

### 問題：確認電郵連結壞了（點擊後顯示錯誤）

**最大可能：** `BASE_URL` 設定錯誤
- 去 Vercel 後台 → Environment Variables
- 確認 `BASE_URL` 係你部署後的真實域名
- 設好後要 Redeploy

### 問題：病人話提醒電郵沒收到

**排查步驟：**
1. 確認 cron 任務有在跑（Vercel logs 搵 `[cron]` 字眼）
2. 確認病人有填電郵
3. 確認預約時間有超過 24 小時前

### 問題：醫師控制台入唔到

**通常原因：** 帳號未有 `staff` 權限
- 去 Supabase → `staff_roles` 表
- 加入帳號嘅 user_id + role

## 十一、主要技術術語解釋（新手版）

| 術語 | 解釋 |
|------|------|
| **Next.js** | React 的框架，負責前端頁面和後端 API |
| **TypeScript** | JavaScript 加上型別檢查，減少 bug |
| **API Route** | 後端程式碼，處理請求（例如查時段、落單） |
| **Supabase** | 雲端資料庫服務，你的核心資料都在這 |
| **Drizzle ORM** | 操控 Neon 資料庫的工具 |
| **Vercel** | 你的系統部署在這裡，連接 GitHub 自動部署 |
| **OAuth** | 用 Google 帳號登入的技術（不需自己管密碼） |
| **Cron** | 定時自動執行的任務（例如每小時寄提醒） |
| **ENV / 環境變數** | 敏感設定（API key 等），不放代碼，放設定檔 |
| **JWT / Token** | 一種加密令牌，用於改期/取消連結驗證 |
| **freeBusy** | Google Calendar API 的查詢方法，回傳哪些時段有人 |
