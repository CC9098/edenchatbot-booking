Mode 判定骨幹

User Message -> Rule Engine -> (optional) Semantic Router -> Final Mode
  • B 模式優先處理預約意圖
  • Router 低信心會 fallback rule mode
  • 最終只會是 G1/G2/G3/B

高風險規則

  • 不可未 call function 就聲稱預約成功
  • 查時段必須走 availability function
  • 登入狀態下要正確處理 user-scoped data

病人主旅程

/ -> /articles or /courses -> /chat -> /booking -> confirmation email -> /reschedule or /cancel
內容、AI、預約已整合到同一網站入口。

B-Mode Intake

  • 必填：姓名、電話、email、首診/覆診、醫師、診所、日期時段
  • 可選：treatmentOptions（按共享 booking treatment option IDs 驗證）
  • 首診額外：DOB、身份證（可選）、性別、過敏、用藥、症狀

後端執行

  • POST /api/availability 查時段
  • POST /api/booking 建立預約
  • POST /api/doctor/bookings 姑娘代客建立預約（staff-auth + booking_intake）
  • 同步 booking_intake + Google Calendar + Gmail
  • GET /api/cron/booking-reminders（CRON_SECRET 保護；掃描 now+23h 至 now+25h 視窗，派發 24h 提醒）

WhatsApp 通知策略

  • lib/chatwoot-whatsapp.ts 採用 template-preferred 發送
  • 同步模板會先按設定的 template 名稱順序排序，再按語言偏好排序
  • 模板參數候選已支援 body-only 組合（適配移除 URL 按鈕後只留 body placeholders 的確認模板）
  • manage-link URL 按鈕參數會優先抽取 path+query（配合模板 base domain 串接），再 fallback token
  • /api/chatwoot/agent-bot 的「預約服務」會進入子選單（預約/更期/取消）；更期或取消會發對應 manage-link 訊息
  • manage-link 發送流程仍為：優先 template 按鈕，輪詢送達狀態，失敗訊息刪除後 fallback 文字
  • lib/widget-manage-token.ts 抽出 manage access token 簽署/編碼邏輯，供 Chatwoot 及 widget booking 共用
  • /manage/[...legacy] + lib/legacy-manage-link.ts 會處理 legacy 模板連結並 redirect 到 canonical manage URL
  • 如屬 active conversation 且 template 失敗，fallback 文字訊息避免中斷送達
  • lib/whatsapp-booking.ts 統一確認/取消/改期模板參數
  • lib/booking-reminder-payload.ts 統一 24h 提醒 payload 解析；若缺 email 會跳過 email 但不阻斷 WhatsApp 提醒

Holiday 封鎖來源

  • POST /api/availability 透過 lib/holiday-store.ts 取假期封鎖資料
  • 來源為 Supabase holidays + legacy storage，並做去重合併
  • 單一來源失敗時，如另一來源有資料，仍可維持封鎖判斷

公開頁

/, /articles, /courses, /chat, /booking

操作頁

/reschedule, /cancel, /embed

後台頁

/doctor, /doctor/booking, /doctor/patients/[id], /doctor/content/articles

核心 API

  • /api/chat (legacy/simple)
  • /api/chat/booking/create (bridge booking create；支援可選 treatmentOptions)
  • /api/chat/v2 (main intelligent flow)
  • /api/availability + /api/booking
  • /api/doctor/bookings (staff console 代約建立)
  • /api/cron/pos-sync-daily (CRON_SECRET 保護；輸出每日 POS sync 候選清單/摘要)
  • /api/cron/booking-reminders (CRON_SECRET 保護；24h 提醒派發，支援 dryRun=1)

核心資料表

  • Booking: doctors, doctor_schedules, holidays, booking_intake
  • Chat/Care: chat_messages, patient_care_profile, care_instructions
  • Content: articles, courses, course_lessons
